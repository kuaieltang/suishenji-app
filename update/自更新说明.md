# 自更新说明

App 会自己检查新版本、自己下载安装包，但**最后那一下「安装」需要你点确认** ——
这是安卓的系统设计，普通应用不允许静默安装 APK（只有应用商店和有系统特权的应用可以）。

## 怎么工作

```
打开 App
  └─ 每天查一次 update/version.json（同一天内不重复查）
       ├─ 没有新版本 → 什么都不做
       └─ 有新版本
            ├─ 在 Wifi 上   → 自动下载（带进度、断点续传、sha256 校验）
            └─ 在流量上     → 先问一句，你说下才下
                  └─ 下好后弹「安装」→ 系统安装界面 → 你点安装 → 完成
```

几个细节：

- **一天只查一次**，不会每次打开都打网络（手动点「检查更新」不受此限制）
- **只在 Wifi 下自动下载**；流量上会先问，安装包约 11 MB
- **下载完会校验 sha256**，对不上就删掉重来，不会给你一个坏包
- **断点续传**：中途断了，下次从断点接着下
- 安装包按 versionCode 命名（`suishenji-5.apk`），新旧包不会互相覆盖
- 首次安装需要你在系统设置里允许「来自此来源的应用」，App 会带你过去

## 发一个新版本要做什么

1. 改代码、把 `app/build.gradle.kts` 里的 `versionCode` 加一、`versionName` 改成新号。
2. 编译发布包：`tools\build.cmd assembleRelease`
3. 写更新说明（一行一条），生成清单：

   ```bat
   .build\python\python.exe tools\make_version_json.py ^
      <versionCode> <versionName> ^
      app\build\outputs\apk\release\app-release.apk ^
      dist\update\version.json ^
      dist\update\notes-<版本>.md
   ```

4. 把 APK 按清单里的名字复制进 `dist\update\`（脚本会告诉你叫什么）。

   > ⚠️ **顺序很重要**：`version.json` 里的 sha256 必须和**最终上传的那个 APK**
   > 完全一致。AGP 构建不是逐字节可复现的 —— 每重新编译一次，哈希就会变。
   > 所以务必在**最后一次编译之后**再跑生成脚本，中间不要再重新编译。
   > 生成完可以用这个检查三者（`dist` 里的 APK、`update` 里的 APK、清单里的 sha256）是否一致。

5. 把 `dist\update\` 里的 `version.json` 和那个 APK 传到
   `kuaieltang/suishenji-app` 仓库的 `update/` 目录下。

**注意**：`versionName` 只用于显示，App 比的是 `versionCode`。
每发一版 `versionCode` 必须严格加一，否则手机不会认为是新版本。

## 站点上要有这些文件

```
https://kuaieltang.github.io/suishenji-app/update/version.json
https://kuaieltang.github.io/suishenji-app/update/suishenji-<versionCode>.apk
```

顺带一提，字体走的是同一个仓库的 `fonts/` 目录，两者互不影响。

## 签名不能变

自更新的前提是新旧 APK 用**同一个签名**。这个项目的签名固定是
`keystore/suishenji.jks`（口令在 `keystore/signing.properties`）。

**这个文件千万别丢、别换**：换了签名，新版本在手机上装不上，
只能卸载重装（那会清掉本机还没上传的记录）。
